# 요구사항 정의서

콘솔 기반 인증 · 포인트 · 연산 시스템 (실습용)

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 목적 | 회원 인증, 포인트 충전, 수식 연산(포인트 차감)을 제공하는 실습용 시스템 |
| 형태 | 콘솔 애플리케이션 |
| 범위 | 회원 관리, 로그인 이력, 포인트 충전/조정, 수식 연산(포인트 차감) |
| 보안 | 실습용이므로 **제외** (비밀번호 해시, 로그인 잠금, 카드 정보 암호화 등을 하지 않음) |

## 2. 회원 관리

### 2.1 회원 가입
- ID와 이름만 입력하면 가입된다.
- 이미 존재하는 ID는 가입할 수 없다. (`admin` 포함)
- 빈 값은 허용하지 않는다.

### 2.2 로그인
- **ID만 입력**하면 바로 인증된다. (비밀번호 없음)
- 존재하지 않는 ID는 로그인할 수 없다.
- 로그인 **실패는 기록하지 않는다.**
- 로그인 직후 "마지막 접속 시간, 총 로그인 횟수"를 보여준다.

### 2.3 회원정보 수정
- 이름을 수정할 수 있다.
- **신용카드 정보**를 입력할 수 있다.
  - 카드번호: 숫자 6자리
  - 카드 비밀번호: 숫자 2자리
  - 형식에 맞지 않으면 거부한다.
- 신용카드는 **회원당 1장만** 등록한다. 새로 입력하면 기존 정보를 덮어쓴다.
- 가입 시에는 신용카드 정보가 없다. (`null`)

### 2.4 로그인 이력
- 로그인에 성공할 때마다 로그인 일시(날짜, 시, 분, 초)를 이력에 **추가**한다.
- 이력은 **전부 보관**한다. (삭제 · 개수 제한 없음)
- **로그인 횟수**와 **최근 로그인 시간**은 별도로 저장하지 않고, 이력에서 계산한다.
  - 횟수 = 이력의 개수
  - 최근 로그인 시간 = 이력의 마지막 항목
- "내 이력 보기" 메뉴(7장)에서 로그인 이력을 조회할 수 있다.

### 2.5 관리자 계정
- ID `admin`인 관리자 계정이 **미리 존재**한다.
- 프로그램 시작 시 데이터 파일에 `admin`이 없으면 **자동으로 생성**한다. (파일이 없는 첫 실행 포함)
- 로그인 방식은 일반 회원과 동일하다. (ID만 입력)
- 로그인한 회원이 관리자이면 관리자 메뉴가 추가로 보인다.
- 로그인 이력은 일반 회원과 동일하게 기록한다.
- 관리자는 **특정 회원의 이력**(로그인 이력, 결제 이력)을 조회할 수 있다. (2.6 참고)

### 2.6 관리자의 회원 이력 조회
- 관리자는 회원 ID를 입력하여 해당 회원의 이력을 조회할 수 있다.
  - 로그인 이력 (일시 목록, 총 로그인 횟수, 최근 로그인 시간)
  - 결제 이력 (일시, 금액, 결과)
- 존재하지 않는 ID이면 거부한다.
- 조회만 가능하고, 이력을 수정하거나 삭제할 수는 없다.
- 일반 회원은 본인의 이력만 조회할 수 있다.

## 3. 포인트

### 3.1 포인트 종류

| 종류 | 발생 경로 | 관리자 임의 조정 |
|---|---|---|
| 결제 포인트 | 신용카드 결제로 충전 | **불가** |
| 보너스 포인트 | 관리자가 지급 | 추가 / 제거 가능 |

- 두 종류는 **따로 저장**한다. (합계만 저장하지 않는다.)
- 포인트 잔액 = 결제 포인트 + 보너스 포인트
- 결제 포인트는 충전(결제)과 연산 차감으로만 변하고, 관리자 기능으로는 변경할 수 없다.

### 3.2 포인트 충전 (결제)
- 충전 금액을 직접 입력한다. **1원 = 1포인트**
- 흐름
  1. 충전 금액 입력
  2. 신용카드 정보가 없으면 중단하고 회원정보 수정에서 먼저 등록하도록 안내
  3. 결제 모듈 호출
  4. 성공이면 결제 포인트를 충전하고 즉시 저장
  5. 실패이면 충전하지 않고 오류를 안내
- 금액은 1 이상의 정수만 허용한다.
- 결제를 시도할 때마다 **결제 이력**을 기록한다. (3.2.1 참고)

#### 3.2.1 결제 이력
- 결제 모듈을 호출한 결과를 **성공/실패 모두** 이력에 추가하고 즉시 저장한다.
  - 신용카드 미등록 등으로 결제 모듈을 호출하기 전에 중단된 경우는 기록하지 않는다.
- 기록 항목: 결제 일시(날짜, 시, 분, 초), 금액, 결과(`SUCCESS` / `FAIL`)
- 이력은 **전부 보관**한다. (삭제 · 개수 제한 없음)
- "내 이력 보기" 메뉴(7장)에서 본인의 결제 이력을 조회할 수 있다.

### 3.3 결제 모듈 (Mock)
- 결제 모듈은 카드 정보와 금액을 받아 성공/실패를 돌려준다.
- 이번 범위에서는 실제 결제 연동 없이 **항상 성공**을 반환한다.
- 이후 실제 결제 연동으로 교체하더라도, 결제를 요청하는 쪽의 동작은 바뀌지 않는다.

### 3.4 잔액 확인
- 로그인한 회원은 자신의 포인트 잔액(결제 포인트, 보너스 포인트, 합계)을 확인할 수 있다.

### 3.5 관리자 보너스 포인트 조정
- 관리자는 임의의 회원에게 보너스 포인트를 **추가**할 수 있다.
- 관리자는 임의의 회원의 보너스 포인트를 **제거**할 수 있다.
  - 보유한 보너스 포인트보다 많이 제거하려 하면 **거부**한다. (일부만 제거하지 않음)
- 대상 회원이 존재하지 않으면 거부한다.
- 금액은 1 이상의 정수만 허용한다.
- 변경 시 즉시 저장한다.

### 3.6 포인트 차감 순서
- 차감할 때는 **보너스 포인트를 먼저** 사용한다.
- 보너스 포인트가 부족하면 남은 금액을 결제 포인트에서 차감한다.
- 두 종류를 합쳐도 부족하면 차감하지 않는다. (일부만 차감하지 않음)

## 4. GPU 연산 기능

> 이름은 "GPU 연산"이지만 실제로는 **CPU**로 계산한다. 화면과 문서에서만 GPU 연산으로 표기한다.

### 4.1 입력
- 계산 수식을 **텍스트**로 입력한다. (예: `3 + 4 * (2 - 1.5)`)
- 지원 범위: 정수, 소수, 사칙연산(`+ - * /`), 괄호, 음수(`-5 + 3`), 공백
- 수식을 파싱하여 연산한다.

### 4.2 사전 검증
- 연산을 시작하기 **전에** 문법을 검증한다. (괄호 짝, 연산자 위치, 허용되지 않는 문자 등)
- 문법 오류이면 포인트를 차감하지 않고 오류를 안내한다.

### 4.3 포인트 차감 규칙
사칙연산을 **1회 수행할 때마다** 포인트가 차감된다.

| 연산 | 정수 연산 | 소수점 포함 연산 (5배) |
|---|---|---|
| `+`, `-` | 1 포인트 | 5 포인트 |
| `*` | 10 포인트 | 50 포인트 |
| `/` | 100 포인트 | 500 포인트 |

- 예: `5 * 0.1` → 10포인트가 아니라 **50포인트** 차감
- 괄호와 단항 음수 기호(`-5`의 `-`)는 연산 횟수에 포함하지 않는다.
- 차감은 각 연산을 수행하기 **직전**에 한다. 차감 순서는 3.6을 따르고, 변경마다 즉시 저장한다.
- 연산마다 차감 내역을 화면에 출력한다. (예: `3 * 2 → 10포인트 차감, 잔액 90`)

### 4.4 "소수점이 포함된 연산"의 기준
- 소수 여부는 **숫자(값)가 가지는 성질**이다.
  1. 입력한 숫자에 소수점이 적혀 있으면 소수이다. (`1.0`, `0.1`)
  2. 나눗셈 결과가 `3.5`처럼 소수로 나오면, 그 값은 그때부터 소수이다.
  3. 소수가 섞인 연산(피연산자 중 하나라도 소수)의 **결과도 소수**로 유지한다. (`1.0 + 2 = 3.0`, 이후 `3.0 * 2`도 50포인트)
  4. 나누어떨어지는 정수 나눗셈의 결과는 **정수**이다. (`6 / 2 = 3`) 단, 피연산자가 소수이면 3번에 따라 결과도 소수이다. (`6.0 / 2`)
- 연산에 쓰이는 피연산자 중 **하나라도 소수이면** 그 연산은 5배 비용이다.
- 예: `7 / 2 + 1`
  - `7 / 2` : 피연산자가 모두 정수 → 100포인트, 결과 `3.5`는 소수
  - `3.5 + 1` : 피연산자에 소수가 있음 → 5포인트

### 4.5 나눗셈과 계산 정밀도
- 나눗셈은 정수 나눗셈이 아니라 실수 나눗셈이다. (`7 / 2 = 3.5`)
- 나누어떨어지지 않는 경우 소수 **10자리**까지 계산한다.

### 4.6 연산 중단과 재개
- 연산 도중 포인트가 모자라면 해당 연산에서 **일시 중지**한다.
  - 안내: 몇 번째 연산에서 중지되었는지, 필요한 포인트와 보유한 포인트
  - 중지된 연산을 수행하기 전에 멈추므로 포인트가 일부만 차감되지 않는다.
- 중지된 연산은 **회원 데이터에 저장**한다. (프로그램을 종료했다 다시 켜도 이어서 진행 가능)
- 포인트를 충전하면 "연산 이어서 진행" 메뉴로 **중지된 지점부터** 이어서 진행한다.
  - 이미 수행한 연산은 다시 차감하지 않는다.
  - 중간 결과값은 소수 여부와 함께 복원한다.
- 중지된 연산은 회원당 **1개**만 가진다.
  - 중지된 연산이 있을 때 새 수식을 입력하면, 기존 연산을 버릴지 확인을 묻는다.
  - 확인하면 기존 연산을 폐기하고, 거부하면 새 수식을 시작하지 않는다.

### 4.7 오류 처리
- **0으로 나누기**: 오류로 연산을 종료하고 중지 상태도 남기지 않는다. 이미 차감된 포인트는 돌려주지 않는다.
- 문법 오류: 4.2에 따라 시작 전에 막는다.
- 연산 이력은 기록하지 않는다.

## 5. 데이터 저장

### 5.1 저장 방식
- **JSON 파일 기반**으로 저장한다. 파일 위치는 실행 폴더의 `data/members.json`으로 한다.
- 시작할 때 전체를 읽어 오고, 데이터가 **변경될 때마다 즉시 저장**한다.
  - 저장 시점: 회원 가입, 로그인 성공, 회원정보 수정, 포인트 충전, 결제 이력 추가, 보너스 조정, 연산 중 차감, 연산 중지/재개/폐기
- 회원 한 명만 바뀌어도 파일 전체를 다시 쓴다.

### 5.2 안전한 저장 (임시 파일 후 교체)
1. `members.json.tmp`에 전체를 먼저 쓴다.
2. 쓰기가 성공하면 원본 파일과 교체한다.
3. 쓰는 도중 오류가 나도 기존 `members.json`은 손상되지 않는다.

### 5.3 파일 상태별 동작
| 상태 | 동작 |
|---|---|
| 파일이 없음 (첫 실행) | 빈 목록으로 시작하고 `admin` 계정을 생성 |
| `admin` 계정이 없음 | 자동 생성 |
| 파일이 비었거나 JSON이 깨짐 | 오류를 안내하고 종료한다. 원본을 덮어쓰지 않는다. |
| 저장 실패 | 오류를 안내하고 계속 진행한다. |

## 6. 예외 및 입력 검증

| 상황 | 처리 |
|---|---|
| 가입 시 ID 중복 | 거부 |
| 존재하지 않는 ID 로그인 | 거부 |
| 빈 값 입력 | 거부 |
| 신용카드 번호가 6자리 숫자가 아님 | 거부 |
| 신용카드 비밀번호가 2자리 숫자가 아님 | 거부 |
| 신용카드 미등록 상태에서 결제 | 중단하고 등록 안내 |
| 충전/조정 금액이 1 미만이거나 숫자가 아님 | 거부 |
| 보너스를 보유량보다 많이 제거 | 거부 |
| 수식 문법 오류 | 포인트 차감 없이 거부 |
| 0으로 나누기 | 연산 종료, 차감분 환불 없음 |
| 연산 중 포인트 부족 | 일시 중지 후 저장 |
| 메뉴에 숫자가 아닌 입력 | 안내 후 다시 입력 |

## 7. 메뉴 구성

**로그인 전**
1. 회원 가입
2. 로그인
3. 종료

**로그인 후 (일반 회원)**
1. 회원정보 수정 (이름, 신용카드 정보)
2. 내 이력 보기
   - 2-1. 로그인 이력 (일시 목록, 총 로그인 횟수, 최근 로그인 시간)
   - 2-2. 결제 이력 (일시, 금액, 결과)
3. 포인트 잔액 확인
4. 포인트 충전 (결제)
5. GPU 연산 (수식 입력)
6. 중지된 연산 이어서 진행
7. 로그아웃

- "내 이력 보기"는 **로그인한 본인의 이력만** 조회한다.
- 이력은 최신순으로 보여준다.

**관리자 추가 메뉴**
- 보너스 포인트 추가
- 보너스 포인트 제거
- 회원 이력 조회 (회원 ID 입력 → 로그인 이력 / 결제 이력)
